# Known issues

Bugs and limitations we're aware of and have chosen to defer. If you hit one, you're not seeing
something new — and fixes are welcome (see [CONTRIBUTING.md](CONTRIBUTING.md)).

Last reviewed: 2026-08-22 (v0.2.1).

## Installation

### `Add package from git URL` does not work — install from disk

Pasting the repository URL into Unity's **Package Manager ▸ + ▸ Add package from git URL…**
fails, and there is no git URL that fully works. Use **Add package from disk…** and select
`unity-package/package.json`, as described in [INSTALL.txt](INSTALL.txt) STEP 3.

- **Severity:** low (the supported disk install works).
- **Why:** two independent reasons.
  1. Unity looks for `package.json` at the **repository root**. Agen-Link is a monorepo — the
     Unity package lives in `unity-package/`, alongside the `mcp-server/` and `pty-host/` Node
     helpers — so there is nothing at the root for Unity to read.
  2. More fundamentally, the Editor code resolves both helpers as **siblings** of the package
     folder (`PackageInfo.resolvedPath` + `/../mcp-server/…` and `/../pty-host/…`). A git-URL
     install copies only `unity-package/` into `Library/PackageCache/`, whose parent contains
     no such siblings, so the Terminal and the MCP bridge would both fail to start.
- **Note:** appending `?path=/unity-package` to the URL gets past reason 1, but not reason 2 —
  the package will import and the C# will compile, but the Terminal and bridge will not run.
  The helpers additionally need a per-machine `npm install` (native `node-pty`, built against
  the local Node/ConPTY), and `Library/PackageCache` is regenerated by Unity, so `node_modules`
  cannot live there.

## Terminal

### Maximizing the Agen-Link window drops the terminal session

Deliberately maximizing and then restoring the Agen-Link Editor window — double-clicking the window
tab, or Unity's "Maximize" command — recreates the window, and the embedded terminal loses its
connection to the running CLI session.

- **Severity:** low.
- **Note:** the *accidental* trigger is gone — pressing <kbd>Shift</kbd>+<kbd>Space</kbd> while typing
  no longer maximizes the window, because the Terminal tab now captures the keyboard while focused. So
  this only happens on an intentional maximize.
- **Workaround:** avoid maximizing the window mid-session; if you do, press **⟳ Restart** to start a
  fresh session. The underlying CLI process keeps running, but scrollback from before the maximize is
  not restored to the new view.

### Mouse clicks and drags are not forwarded to the CLI

The terminal forwards the scroll wheel, text selection/copy, paste, and the keyboard (including
<kbd>Shift</kbd>+<kbd>Tab</kbd>), but mouse **clicks and drags** are not yet forwarded to the child
CLI. Full-screen terminal apps that rely on mouse positioning won't receive those events.

- **Severity:** low.
- **Workaround:** use keyboard navigation.
